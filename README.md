# 实训学时合规与冻结服务

该服务汇聚学员签到、导师确认和请假修正事件，按培养方案与时区重放学时状态，并保存可追溯的学期冻结快照。项目还提供导师分配、证明材料、豁免复核、规则版本、名额、通知和数据留存等领域模块，供后续业务扩展时复用统一的状态与审计约束。

## 异常学时复核案件

负向修正、超长签到（默认阈值 12 小时，可在检测时覆盖）和重叠活动不再直接改变学员总学时，而是统一进入复核案件：

- **检测立案**：`POST /api/plans/{plan}/cases/detect` 扫描事件流并立案。每个异常按「培养方案 + 规则 + 来源事件」生成确定性指纹，同一异常无论案件处于何种状态都不会重复立案；并发检测也只立案一次。
- **状态机**：`detected → claimed → resolved / dismissed`，已裁决案件可由管理员 `reopen` 后重新认领裁决；`merged` 为终态。非法流转返回 409。
- **认领与权限**：所有案件接口要求 `X-Actor-Id` 与 `X-Actor-Role`（`reviewer` / `admin`）请求头。认领通过数据库条件更新保证并发下只有一人成功；补证、裁决仅限案件处理人或管理员；复开、合并、拆分仅限管理员。
- **补证与裁决**：`evidence` 追加证据材料；`adjudicate` 通过（`upheld`）时按「目标修正总额 − 已落地修正」的差额生成 `case_correction` 修正事件并关联到案件，驳回（`rejected`）则不产生事件。复开后再次裁决按同一收敛规则追加事件，已落地事件不回滚。
- **合并与拆分**：`merge` 把源案件并入目标案件，目标吸收其指纹与来源事件；`split` 从父案件拆出子案件。`lineage`、`merged_into`、`child_case_ids` 与 `source_event_ids` 保证合并或拆分后仍能追踪原始来源。
- **冻结标注**：未决案件（detected / claimed / reopened）在快照与冻结快照中按学员清晰标注（`pending_cases`，`counts_toward_confirmed: false`），但不计入已确认学时；裁决落地后的修正事件才会进入总学时。

## 运行方式

默认数据保存在项目目录的 SQLite 文件中。安装依赖后执行 `uvicorn app.main:app --host 127.0.0.1 --port 8000`，健康检查地址为 `/health`，业务接口位于 `/api`。
